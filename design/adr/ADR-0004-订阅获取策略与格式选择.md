# ADR-0004：订阅内容获取策略与格式选择

- 状态：已接受
- 日期：2026-10-14
- 决策者：实现方（基于源码审计事实）

## 背景

审计 `src/references/Xboard-master/app/Protocols/` 得到准确的格式分发事实：服务端依据请求中的 `flag`（或 `User-Agent`）选择协议类，各协议类支持的 flag 如下。

| flag | 协议类 | 输出格式 |
|---|---|---|
| `general`、`v2rayn`、`v2rayng`、`passwall`、`ssrplus`、`sagernet` | General | **Base64 编码的节点 URI 列表** |
| `meta`、`verge`、`flclash`、`nekobox`、`clashmetaforandroid` | ClashMeta | ClashMeta YAML |
| `clash` | Clash | Clash YAML |
| `sing-box`、`hiddify`、`sfm` | SingBox | sing-box JSON |
| `shadowrocket`、`loon`、`quantumult x`、`stash`、`surfboard`、`surge`、`shadowsocks` | 各家 | 专有格式 |

源码定位：`app/Protocols/*.php` 的 `$flags` 声明；General 的输出见 `General.php:31-54`。

**关键结论：Xboard 不提供原生 Xray JSON 输出。** 因此若以 ClashMeta YAML 作为主输入，Xray 核心需要一次 YAML→Xray 的转换，复杂度与失真风险都高。

另有一项重要发现：订阅响应带 `subscription-userinfo` 头（`General.php:53`），格式为
`upload=..; download=..; total=..; expire=..`。这意味着账户用量可从订阅响应直接获得，不必额外请求面板接口。

## 决策

1. **主输入格式为 Base64 节点 URI 列表**（请求时声明 `flag=general`）。
   理由：URI 是跨核心、跨客户端的稳定交换格式；Xray 与 sing-box 都能从同一份 UR 导出配置；不依赖任何核心的专有 YAML 变体。

2. **规范化模型是唯一真相**：所有格式先解析为 `domain.Node`，两个核心的编译器只依赖该模型（见 ADR 待立的「标准节点模型」议题）。

3. **Clash YAML 与 sing-box JSON 作为后续导入器**，不代替主链路。
   当前 `shared/subscription` 已实现 URI 列表解析；其余两种格式**已能识别但显式返回「未实现」错误**，不静默失败也不静默跳过。

4. **利用 `subscription-userinfo` 头**：订阅拉取同时返回用量与到期，作为面板接口之外的第二来源；两者若不一致，以面板接口为准并在诊断中标注差异。

5. **声明 flag 而不依赖默认值**：客户端按已选核心主动声明 `flag`，避免服务端返回需要额外转换的格式。首轮统一使用 `general`。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 以 ClashMeta YAML 为主输入 | Xray 需 YAML→Xray 转换，失真风险高；Clash 方言差异大 |
| 以 sing-box JSON 为主输入 | 服务端 JSON 内含它自己的路由/DNS，会与用户的路由策略冲突；且对 Xray 无用 |
| 双核心各自请求不同格式 | 同一用户会得到语义不一致的两份节点集合，切换核心时选择会漂移 |
| 只支持 URI 列表、不支持 YAML | 第三方订阅大量使用 Clash YAML，会削弱 R07 的第三方导入能力 |

## 影响

- 正面：单一解析链路，两个编译器共用输入；不依赖核心专有格式；可离线做契约测试。
- 负面：URI 格式对个别高级参数（如某些 xhttp extra、plugin 参数）表达能力有限，这些字段进入隔离区。
- 缓解：隔离区字段在专业模式中可见；后续可增加 Clash YAML 导入器补齐。
