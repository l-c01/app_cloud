# ADR-0001：目录结构与版本管理方式

- 状态：已接受
- 日期：2026-10-14
- 决策者：用户（提出要求）+ 实现方（方案细化）

## 背景

首轮设计把源码、设计文档、构建目标、参考源码混放在 `design/` 下，并且参考源码快照一度被提交进版本历史（4309 个文件），导致：

1. 目录职责不清：第三方源码与设计文件混在一起。
2. 版本管理失效：无法区分「自己写的代码」与「供应商代码」的历史。
3. 交付产物无处安放。

## 决策

采用三个顶层目录，职责互斥：

| 目录 | 职责 |
|---|---|
| `design/` | 只放设计文件（文档、契约、Schema、ADR、审计、计划） |
| `src/` | 源码。`src/references/` 第三方只读参考；`src/versions/<版本>/` 本项目各版本源码 |
| `output/` | 对外输出（构建产物、报告、导出包），不入 git |

版本管理采用**一个 git 仓 + 目录承载版本 + tag 标记**：

- 版本号遵循语义化版本，目录名即版本号，如 `src/versions/0.1.0/`。
- 发布时打同名 tag：`v0.1.0`、`v0.2.0`。
- 版本之间用 `git diff v0.1.0 v0.2.0` 对比。
- 历史版本目录只读，不得就地重写；新版本从上一版本复制后修改。
- `src/references/**` 与 `output/**` 由 `.gitignore` 排除（`output/README.md` 除外）。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 每个版本目录各自一个独立 git 仓 | 版本间无法对比；git 不允许嵌套仓，`src/versions/` 会成为超项目，容易误操作 |
| 用分支区分版本 | 只能检出一个版本，无法在同一工作区对照多版本；历史版本容易被 force-push 覆盖 |
| 参考源码入库 | 体积大、第三方许可、污染历史、与「自己写的源码」无法区分 |

## 影响

- 正面：职责清晰、可回溯、可直接推送 GitHub 做手动构建。
- 负面：切换版本需 `git checkout` 或复制目录；`src/references/` 不入库意味着换机器需重新获取快照。
- 缓解：参考快照的来源与版本事实记录在 `design/audit/source-register.md`，可据此重新获取。

## 复现要求

结构或约定变更时，必须同步更新本文档与 `design/architecture/repository-layout.md`。
