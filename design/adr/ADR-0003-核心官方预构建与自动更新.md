# ADR-0003：核心采用官方预构建二进制，客户端内置自动更新

- 状态：已接受（用户决定）
- 日期：2026-10-14
- 决策者：用户

## 背景

Xray 与 sing-box 是独立的代理核心项目，维护成本高、构建依赖重（Go 版本不同、CGO、平台专用驱动等）。

用户明确决定：“使用已有的 xray/singbox 构建好的核心即可，不需要单独编译特殊版本，直接在软件内部配置内核自动更新。”

## 决策

1. **不编译核心**：本项目不把 Xray / sing-box 源码编译进产物，也不在 CI 中构建核心。
2. **使用官方预构建二进制**：桌面端把官方 Release 的 Xray / sing-box 可执行文件随应用分发（sidecar 进程），或首次启动时下载。
3. **客户端内置核心自动更新**：应用内提供“内核管理/自动更新”能力：
   - 检查已安装核心版本与目标锁定版本；
   - 按平台 + 架构下载对应官方预构建产物；
   - 校验固定列表中的 SHA256（**必须校验**，禁止裸下载）；
   - 校验通过后**原子替换**并保留旧版本用于回滚；
   - 更新失败保留旧核心并可重试，不阻塞连接功能。
4. **核心版本锁定**：Xray / sing-box 的具体版本与校验和写入 `versions.lock.json`（`releaseBuildMustRejectNullPins=true`）；自动更新只升级到锁定的下一目标，不“追踪 latest”。
5. **Android 内核分发待 G1 探针**：Android 以库内嵌（AAR）还是预构建二进制由 G1 的绑定探针决定；若走预构建核心，同样遵守 SHA256 校验与原子替换原则。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 从源码编译两个核心 | 与用户明确决定冲突；构建重、双核心 bloat、维护成本高 |
| 客户端内置“自动检查 GitHub latest 并升级” | 不可复现、不安全；必须是“锁定版本 → 显式升级”流程 |
| 依赖系统包管理器版本 | 版本不可控、跨平台不一致、用户机器上可能不存在 |

## 影响

- 正面：产物体积可控（只带所选核心）、无需维护双核心构建矩阵、升级由客户端统一管理。
- 负面：分发时需附带第三方二进制的许可证与 NOTICE；下载来源需可离线/镜像策略。
- 缓解：固定校验和、失败回滚、版本锁文件；`src/references/` 中的核心源码仍作为**配置格式与 CLI 契约**的只读参考。

## 后续动作

1. 固定 Xray / sing-box 目标版本与官方校验和，写入 `versions.lock.json`（G0 收尾/G1）。
2. 设计核心里程碑：`GetCapabilities` 返回核心版本；`CoreUpdater` 负责检查/下载/校验/原子替换。
3. 在 `deploy/packaging/` 与手动构建工作流中定义“打包附带核心”或“首启下载”两种路线并记录。
